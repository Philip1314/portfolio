Project Overview

Role: Operations Data Specialist / Support Analyst

Tools: Google Sheets, Excel, Advanced Formulas (XLOOKUP, INDEX/MATCH, QUERY, ARRAYFORMULA, REGEXREPLACE), Pivot Tables, Conditional Formatting.

Objective: Clean, structure, and analyze 10,000+ raw, unstructured operational support logs (containing mixed POS integration errors, menu update tickets, and refund dispute entries) into an automated, executive-ready dashboard.

Phase 1: Problem Statement & Raw Data Audit

The operations team was working with raw, unformatted CSV exports from CRM and POS logging systems containing critical errors:

  • •
    Inconsistent Formatting: Mixed date formats (YYYY-MM-DD vs MM/DD/YY), inconsistent casing (pos error, POS Error, P.O.S. Error), and whitespace noise.
  • •
    Missing & Corrupted Data: Blank Merchant IDs, string values in numeric refund columns (e.g., "$ 45.50", "N/A"), and duplicate ticket IDs from re-opened emails.
  • •
    Lack of Structure: High-volume raw data without automated categorization or key SLA metrics for leadership.

Phase 2: Data Cleaning & Scrubbing Pipeline

1. Deduplication & Whitespace Trimming

Applied TRIM() and CLEAN() across all text fields. Used Google Sheets Data Cleanup > Remove Duplicates on unique Ticket_ID keys to eliminate re-opened email duplicates while keeping the latest record.

2. Error Detection & Regex Numerical Scrubbing

Combined IFERROR() with regex parsing formulas to convert corrupt text values into clean numeric floats:

=IFERROR(VALUE(REGEXREPLACE(C2, "[^0-9.]", "")), 0)
3. Standardized Categorization via XLOOKUP

Built a Metadata Lookup Table mapping raw error codes to normalized categories without range errors:

=XLOOKUP(Raw_Error_Code, Ref_Table!A:A, Ref_Table!B:B, "Unassigned / Under Review")

Proactive Knowledge Base & SOP Redesign

Optimizing internal operating procedures, eliminating friction points, and resolving root causes before ticket creation.

01

Liquor Stores POS Integration Workflow Redesign

The Operational Gap: The previous SOP required agents to ask merchants for their POS provider name first before checking if the store was managed by an Account Manager. If an account had no Account Manager (a platform employee managing the store), integration could not be offered regardless of the POS provider. This caused prolonged interactions and negative merchant experiences.

The Solution & Action Taken: Updated the SOP and filed Jira requests to reorder verification steps. Agents now verify Account Manager status as the mandatory first gatekeeper. If unmanaged, integration is declined immediately before requesting POS details, saving time and eliminating frustration.

02

POS Delivery Configuration & Root Cause Routing

The Operational Gap: Merchants with POS integrations experiencing unaccepted orders while configured for delivery by their own staff were previously routed into unnecessary Jira tickets. The root cause stemmed from incompatible POS provider configurations that failed to support self-staff delivery modes.

The Solution & Action Taken: Updated internal KB documentation to instantly identify POS delivery incompatibilities. Instead of filing redundant Jira tickets, agents now inform merchants immediately and provide 2 clear alternatives: either switch to a compatible POS provider or update their delivery mode settings.

Project Overview

Role: Operations Data Specialist / Support Analyst

Tools: Google Sheets, Advanced Formulas (XLOOKUP, QUERY, ARRAYFORMULA, REGEXREPLACE, IFERROR), Pivot Tables, Conditional Formatting, Data Validation, Data Cleanup tools.

Objective: Clean, structure, and analyze 10,000+ raw, unstructured operational support logs (containing mixed POS integration errors, menu update tickets, and refund dispute entries) into an automated, executive-ready Google Sheets dashboard.

Phase 1: Problem Statement & Raw Data Audit

The operations team was working with raw, unformatted CSV exports from CRM and POS logging systems containing critical errors:

  • •
    Inconsistent Formatting: Mixed date formats (e.g., YYYY-MM-DD vs MM/DD/YY), inconsistent casing (e.g., pos error, POS Error, P.O.S. Error), and leading/trailing whitespace.
  • •
    Missing & Corrupted Data: Blank Merchant IDs, text strings in numeric refund columns (e.g., $ 45.50 or N/A), and duplicate ticket IDs caused by re-opened support threads.
  • •
    Lack of Structure: High-volume raw data without automated categorization or central aggregation metrics for leadership.

Phase 2: Data Cleaning & Scrubbing Pipeline

1. Deduplication & Whitespace Trimming

Applied =ARRAYFORMULA(TRIM(CLEAN(A2:A))) across text columns to automatically remove extra whitespace and unprintable control characters. Used Google Sheets native menu pathway Data > Data cleanup > Remove duplicates anchored on unique Ticket_ID keys to eliminate duplicate CRM entries while retaining the latest record.

2. Error Handling & Standardized Formulas

Combined IFERROR() with REGEXREPLACE() to strip non-numeric characters (like currency symbols and text) and convert corrupted text strings into clean decimal floats:

=IFERROR(VALUE(REGEXREPLACE(C2, "[^0-9.]", "")), 0)

Standardized date fields into standard ISO dates (YYYY-MM-DD) using =DATEVALUE() and explicit column formatting (Format > Number > Custom date and time) for accurate time-series analysis.

3. Dynamic Categorization via XLOOKUP

Created a dedicated Metadata Lookup Sheet (Ref_Table) mapping raw vendor strings and error codes to normalized operational categories (Integration Handshake Failure, Non-POS Menu Customization, Inaccurate Order Refund Dispute). Implemented XLOOKUP across master rows for dynamic lookups without index breakage risk:

=XLOOKUP(Raw_Error_Code, Ref_Table!A:A, Ref_Table!B:B, "Unassigned / Under Review")
